# KMP Phase 2b — Room → Room-KMP (done)

Part of the [KMP migration roadmap](KMP_MIGRATION_ROADMAP.md). Phase 2 ("share data access") is
sliced; [2a](KMP_PHASE2A.md) moved network + datastore. **2b moves `:core:database` (the Room
cache) into `commonMain`** so the DAOs, entities and the database compile for Android and iOS off
one source set. 2c moves `:core:data`.

## Toolchain bump (required by Room-KMP)
Room-KMP 2.7's Native klibs are produced by **Kotlin 2.1.10** (klib ABI `1.201.0`); a Kotlin 2.0.21
compiler (ABI `1.8.0`) can't read them. So the project moves **Kotlin 2.0.21 → 2.1.20**. Every other
dependency (Ktor 3.0.3, coroutines 1.9.0, kotlinx-serialization 1.7.3, kotlinx-datetime 0.6.1, Koin
4.0.3, lifecycle-viewmodel 2.8.2, DataStore/okio) was built with older Kotlin and stays readable by
the newer compiler, so nothing else had to move.

**KSP stays on the KSP1 line (`2.1.20-1.0.32`).** KSP2 (`-2.0.x`) fails Room's Native symbol
processor with `cannot find required type kotlin.coroutines.Continuation` on suspend DAOs.

## What changed
- **Room 2.6.1 → 2.7.1 (KMP)** + the **bundled SQLite driver** (`androidx.sqlite:sqlite-bundled`)
  which is common code and runs on both platforms.
- `:core:database` is now a **KMP module** (`nearaid.kmp.library` + `com.google.devtools.ksp` +
  the `androidx.room` Gradle plugin for schema export). DAOs (`CacheDaos`), entities
  (`CacheEntities`) and `NearAidDatabase` moved to `commonMain` **unchanged**.
- `NearAidDatabase` gained `@ConstructedBy(NearAidDatabaseConstructor::class)` + the
  `expect object NearAidDatabaseConstructor : RoomDatabaseConstructor<NearAidDatabase>` that Room-KMP
  requires (the `actual` is generated by the Room compiler per target).
- **KSP is per-target** (`kspAndroid` + `kspIosX64/Arm64/SimulatorArm64`) so the generated database
  exists for every target.
- **DB provisioning is `expect`/`actual`** via `databasePlatformModule` (Koin): Android builds from
  `context.getDatabasePath()` with `Dispatchers.IO`; iOS builds from `NSDocumentDirectory` with
  `Dispatchers.Default`. Both use `BundledSQLiteDriver()` (common) and
  `fallbackToDestructiveMigration(dropAllTables = true)`. The common `databaseModule` exposes the DAOs.
- Deleted the now-unused `nearaid.android.room` convention plugin (Room setup lives in the module).

## Verified — both platforms
- `:app:assembleDebug` + `testDebugUnitTest` green under Kotlin 2.1.20.
- `:core:database:compileDebugKotlinAndroid` + `:core:database:compileKotlinIosSimulatorArm64` green
  — Room's KSP generates the Android and iOS databases; the `Continuation` KSP2 issue is avoided by
  the KSP1 pin.
